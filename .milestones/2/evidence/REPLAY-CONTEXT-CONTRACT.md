## 1. The failure taxonomy — the contradiction resolved

Two outcomes, never conflated, and a replayer must report which.

**CONTEXT REFUSAL** — the context is unusable; replay never starts. No claim is
made about the corpus.

- `schema` or `version` unrecognised;
- `corpus.contentSha256` does not equal the corpus file's digest;
- the table fails canonical validation (§3): missing entry, duplicate key,
  non-`Nat` key or value, non-contiguous domain, negative value;
- a threshold is queried at `n` outside the declared domain (§4);
- an auth semantics token the replayer does not implement.

**CONFORMANCE MISMATCH** — the context is structurally valid and fully usable;
replay ran and a step disagreed.

- a **structurally valid but different** declared policy: the table is
  well-formed and complete, and replaying under it produces a step that
  disagrees with the stored bytes.

That is the resolution: **a wrong-but-valid policy is a mismatch; a malformed,
incomplete, or unbound context is a refusal.** Revision 1 collapsed them.

A replayer that reports "corpus does not match" when the true cause was a
malformed context teaches its reader to distrust real mismatches, which is the
whole failure mode this contract exists to prevent.

## 2. Trust boundary — which bytes are authoritative

Stated because NOTE-007 is right that a self-carried hash proves nothing.

| bytes | trusted? | how established |
|---|---|---|
| the sidecar's own bytes | **only as far as the channel that delivered them** | The sidecar cannot authenticate itself. Its integrity comes from the repository that carries it: it is a tracked file, and the corpus gate re-emits and byte-compares it exactly as it does the corpus. **Whoever trusts the checkout trusts the sidecar; nobody else should.** |
| `corpus.contentSha256` | **operative** | binds *this* sidecar to *those* corpus bytes. Detects pairing errors, not forgery: an attacker editing both is not addressed and is out of scope. |
| `policies.*.table` | **the sole authority for replay** | not derived, not verified against Lean by the replayer, not cross-checked against `name`. What the replayer executes. |
| `policies.*.source.*` | **provenance only, never operative** | records which declaration and which Git blob the table was generated from, so a human or a Lean-side gate can detect drift. **A replayer must never resolve it**, and its presence authenticates nothing. |
| `generatedFrom` | provenance only | §6 |

**The independent verification lives on the Lean side, not in the replayer.**
The exporter gate re-derives the table from the named declaration and requires
equality. That is what makes the table trustworthy; the sidecar merely carries
the result. A replayer in another language checks structure (§3) and domain
(§4) and nothing else — it has no way to verify a Lean declaration and must not
pretend to.

## 3. Canonical table validation

A `table` is a list of `[key, value]` pairs. It is **valid** iff all hold; any
failure is a context refusal naming the rule:

1. every key and every value is a non-negative integer;
2. keys are strictly increasing;
3. keys are contiguous from `0`: the key set is exactly `{0, 1, …, N}` for some
   `N`. `N` **is** the domain — there is no separate `domainMax` field to
   disagree with the table;
4. no duplicate key;
5. the list is non-empty;
6. the encoding is exact integers, not floats. `[[2, 1.0]]` is a refusal.

Removing `domainMax` is deliberate: revision 1 let a declared bound and the
table's actual extent disagree. The domain is now a property of the table.

Monotonicity of values is **not** required. `zeroThreshold` is constant and
must remain expressible; a policy is not obliged to be non-decreasing.

## 4. Domain coverage is over queries, not over visible franchises

The load-bearing correction.

**Every threshold query the replay actually performs must fall inside the
table's domain.** Not "every franchise size appearing in the output" — those
differ, because:

- `sweepClosures` re-evaluates **every open question** against the
  post-transition franchise, so one transition can query the threshold several
  times at a size no stored state displays;
- a franchise can change and change back within a transition, so an
  intermediate size is queried and never appears anywhere;
- a question closing removes it from `openQuestions`, so the size at which it
  was evaluated may be invisible in the post-state.

A replayer therefore checks the domain **at the point of query**, not by
scanning states beforehand. A query outside the domain is a **context
refusal**, never an extrapolation and never a mismatch.

The generating side has the same obligation: the exporter emits a table whose
domain covers every query the generation performed, and its gate fails if it
does not. That obligation is stated here so `#75` inherits it.

## 5. Proposed bytes

One sidecar per corpus, beside it, named `<corpus>.context.json`. Never inside
the corpus file.

```json
{
  "schema": "reactivegas.replay-context",
  "version": 1,
  "corpus": {
    "path": "corpus/integrated.json",
    "contentSha256": "1f173aec9c3afd9cb95265e4be2966b9316e810a969d9fc40f672b17120f3675"
  },
  "policies": {
    "threshold": {
      "table": [[0,0],[1,1],[2,1],[3,2],[4,2],[5,3]],
      "label": "legacyThreshold",
      "source": {
        "declaration": "KelGroups.Vote.legacyThreshold",
        "path": "lean/KelGroups/Vote/Types.lean",
        "gitBlobOid": "<git object id of that file's blob at generation>"
      }
    },
    "backdonateAuth": {
      "semantics": "always-refuse",
      "label": "probeAuth",
      "source": {
        "declaration": "Reactivegas.probeAuth",
        "path": "lean/Reactivegas/Step.lean",
        "gitBlobOid": "<git object id>"
      }
    }
  },
  "generatedFrom": {
    "sourceTree": "<git tree oid of lean/ at generation>",
    "baseCommit": "<the commit the exporter ran against — a PRIOR commit>",
    "exporter": "Reactivegas.CorpusExport"
  }
}
```

### Field notes

- **`contentSha256`** — SHA-256 of the corpus file's **raw bytes**. Not a Git
  object id: Git's blob id is SHA-1 (or SHA-256 in a `sha256` repository) over
  `"blob <len>\0" ++ content`, a different value over different input. The two
  are never interchangeable and the field names now say which is which.
- **`gitBlobOid`** — a **Git object id**, as `git rev-parse HEAD:<path>` yields.
  Provenance only. Named `gitBlobOid`, never `sha256`.
- **`label`** — a human-facing name with **no operative force**. A replayer must
  not branch on it, validate against it, or prefer it to the table. Revision 1's
  `name` plus `semantics` beside `table` created three fields able to disagree;
  now `table` decides and `label` is prose.
- **`semantics`** — retained **only** for `backdonateAuth`, which has no table
  because it is not a numeric function. Enumerated tokens; an unrecognised token
  is a context refusal, never a guess. Today: `always-refuse`. Anything richer
  needs a real encoding, not a name — and if `#76` retires `BackdonateAuth`, this
  field goes with it.
- **`sourceTree` / `baseCommit`** — §6.

## 6. `generatedFrom` without a self-referential hash

Revision 1 asked for the commit containing the generated bytes. That commit does
not exist while the bytes are being generated, and demanding it either forces a
second amending commit or invites a placeholder nobody checks.

Instead, two backward-looking bindings:

- **`sourceTree`** — the Git tree oid of `lean/` at generation. Reproducible: a
  later reader checks out that tree, re-runs the exporter, and compares. This is
  the binding that matters and it is not self-referential.
- **`baseCommit`** — the commit the exporter ran against, necessarily a
  **prior** commit. Convenience for humans; `sourceTree` is the operative one,
  because a dirty tree makes the commit misleading and the tree oid still exact.

If the working tree is dirty at generation, `sourceTree` still records exactly
what was built, and the gate can require the tree to be clean if the desk wants
that stronger property. Not proposed here; named as an option.

## 7. Controls — each derived from a trace that actually distinguishes the case

NOTE-007's requirement: the wrong-policy witness must come from a trace that
genuinely discriminates. A corpus whose every question closes at a franchise
where two policies agree cannot witness anything.

**Precondition on the corpus, checked by the gate before the controls run:**
there exists at least one recorded step whose outcome differs under
`legacyThreshold` and under `zeroThreshold`. If no such step exists, the corpus
is **inadequate as a policy witness** and the gate fails — not because a control
failed, but because the corpus cannot support one. `zeroThreshold` closes
everything positive at once, so a corpus containing any question that stays
`.open`, or any question closing `.negative`, satisfies this. The gate proves it
rather than assuming it.

| # | mutation | required outcome |
|---|---|---|
| 1 | none — shipped sidecar | exit 0 |
| 2 | replace `table` with `zeroThreshold`'s tabulation over the same domain, everything else byte-identical | non-zero, reported as **CONFORMANCE MISMATCH**, and the report names the first discriminating step from the precondition |
| 3 | corrupt one character of `corpus.contentSha256` | non-zero, reported as **CONTEXT REFUSAL** (digest) |
| 4 | delete the highest table entry, so a query lands outside the domain | non-zero, reported as **CONTEXT REFUSAL** (domain), naming the queried `n` |
| 5 | duplicate one table key | non-zero, **CONTEXT REFUSAL** (validation rule 4) |
| 6 | make one table value a float | non-zero, **CONTEXT REFUSAL** (validation rule 6) |
| 7 | set `backdonateAuth.semantics` to an unknown token | non-zero, **CONTEXT REFUSAL** (semantics) |
| 8 | change `label` only | **exit 0** — proves `label` is not operative |
| 9 | restore everything byte-identical | exit 0 |

Rows 2–7 must each be demonstrated failing before they are allowed to pass. Row
8 is the control that keeps `label` from silently becoming a second source of
truth. Row 9 exists because a mutation that fails to restore leaves the tree
dirty and every later row judges the wrong artifact.
